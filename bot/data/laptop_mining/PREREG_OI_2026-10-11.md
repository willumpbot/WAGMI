# PRE-REGISTRATION — does open-interest buildup predict move size? Written 2026-10-11, before the data can answer.

**Status: SEALED. Written when the dataset is 2 days old (1,958 rows, 2026-10-10 → 10-11).
Nothing in this file was chosen after looking at an outcome.**

Every reversal in this project — twelve of them — had one cause: **a test that could not fail.** The
cheapest known defence is to fix the test before the data exists. The OI/premium collector is the first
dataset in this project young enough for that to be possible, so this is the one chance to do it.

The server will quote this file's SHA-256 in a commit on their branch, which makes it tamper-evident.
**If this file is edited after that commit, the pre-registration is void and must be declared void.**

---

## 1. The question, as a falsifiable claim

**H1 (primary).** Among the traded coins on a given day, those with the largest 24h **open-interest
buildup** go on to realise a **larger** move over the next 24h than those with the largest unwind,
*after* accounting for what the volatility forecast already predicts.

**H0.** They do not. The difference is zero.

**Why this question and not a more interesting one.** It is the direct extension of the only finding
that has survived a dedicated red team (`funding_hot`: crowded funding → a move **7.7%** bigger than
forecast). It is a **size** question, not a direction question — seven missions of directional work in
this project produced nothing out of sample, while both surviving findings are about magnitude. And
size is what a swing trader actually controls, through stop width and position size.

## 2. Data — fixed now

- **Source:** `server_exports/ctx_snapshots/YYYY-MM-DD.jsonl.gz`, ~15-minute snapshots.
- **Fields used:** `t` (unix), `c` (coin), `oi`, `prem`, `fund`, `mark`. **No other field may be
  introduced later** without declaring this pre-registration amended.
- **Coins:** whichever the collector covers. Expected BTC, ETH, SOL, HYPE, XRP, NEAR.
- **Daily reduction:** the **last snapshot at or before 00:00 UTC** is the day's observation. Fixed to
  remove any choice of intraday timestamp.
- **Forecast baseline:** `har_move_pct` as logged by the server. If it is unavailable for a coin-day,
  that coin-day is **excluded**, and the exclusion count is reported.

## 3. Predictor — fixed now, no thresholds to tune

- `oi_chg = log(oi_t / oi_{t−1d})` per coin per day.
- **Crowding is cross-sectional by construction:** within each day, rank coins by `oi_chg` and split
  into **terciles**. Top tercile = *building*, bottom = *unwinding*.
- **Terciles, not a tuned cut-point.** A threshold chosen from the data is what killed the
  volume-surge finding; there is no threshold here to choose.
- **Secondary predictor:** `prem` (premium), constructed identically. Reported second, and **labelled
  secondary** so it cannot be promoted to the headline if it happens to look better.
- Cross-sectional, not time-series, for a specific reason: the M10 audit measured cross-coin funding
  correlation at **ρ = 0.33**, which means a level-based test has effective n ≈ the number of
  **calendar days**. Ranking within a day differences out that common market factor.

## 4. Outcome — fixed now

- `y = log(realised_move / har_move_pct)` where `realised_move = (high − low) / open` over the window.
- **Primary horizon: 24h. Secondary: 72h.** Both always reported. 24h is primary because it is
  pre-specified here, not because it will turn out better.
- Same scale as `funding_hot`, so effect sizes are directly comparable to the one finding that held.

## 5. Inference — fixed now

- **Statistic:** mean `y` in the *building* tercile minus mean `y` in the *unwinding* tercile.
- **Clustering: day-block bootstrap**, 4,000 draws, all coins on a sampled day resampled together.
  Day is the cluster; coin is not.
- **The equal-weighted day mean is printed beside every pooled figure.** Not optional.
- **Two-sided, α = 0.05**, split for one interim look (§7).

## 6. Placebo — run and reported BEFORE the real test

**Shuffle the crowding rank across coins within each day**, 2,000 draws, recomputing the statistic
each time. This preserves the market-wide factor and destroys only the coin-specific signal, which is
the correct null for a cross-sectional claim.

- **Report its size** (fraction of draws rejecting at α) **whatever it is.**
- **If size falls outside [0.03, 0.07] the design is VOID** and the result is reported as
  **"untested"**, not as a null and not as a finding. This is the rule that `on_20d_low` and the
  exit-agent replay both failed, and both were correctly voided rather than reported.
- A shuffle **across days** would be the broken placebo I built for the exit agent — it breaks the
  price relationship rather than the signal. **It will not be used.**

## 7. Power, and the date this may be run

SD of `y` is taken as **0.40** from the `funding_hot` work. MDE at 80% power = `2.8 × 0.40 / √n_days`.

| n_days | MDE | meaning |
|---|---|---|
| 19 | 25.7% | useless |
| 56 (8 weeks) | 15.0% | twice the effect sought |
| **106** | **10.9%** | interim look only |
| **212** | **7.7%** | matches the `funding_hot` effect |

**Pre-committed schedule, with alpha split so the interim look does not inflate the error rate:**

- **One interim analysis at n_days ≥ 106, at α = 0.005.** Stop and report only if it clears that.
- **Final analysis at n_days ≥ 212, at α = 0.048.**
- **No other looks.** At 1 observation per coin-day from 2026-10-10, n_days = 212 arrives around
  **2027-05-11**. Until an analysis date, the only thing I report is **the accruing day count.**
- **If I look at an outcome before an analysis date, this pre-registration is void and I will say so
  in this file.**

## 8. Decision rules — fixed now, so the verdict is not a judgement call later

| condition | verdict |
|---|---|
| placebo size outside [0.03, 0.07] | **UNTESTED** — design void |
| CI excludes zero **and** equal-weighted day mean agrees in sign **and** placebo size in band | **FINDING**, with effect size and CI |
| CI excludes zero but pooled and equal-weighted **disagree in sign** | **NOT A FINDING** — report both, attribute to day composition |
| CI includes zero | **NULL**, reported with the MDE so it is readable as "no effect larger than X" |

## 9. Commitments

1. **The result is published whichever way it comes out**, including a flat null, in `OI_BUILDUP.md`.
2. **No new predictor, horizon, coin subset, or threshold** will be introduced after an outcome is
   seen. Any addition is an amendment, declared as one, and reported alongside the original.
3. **No subgroup hunting.** If the primary test is null, I will not go looking for a regime or a coin
   where it works and report that instead. That is what produced `btc4h=against` — the best of 22
   slices on 27 outcomes in one week — which I declined to propose.
4. **Power is stated before the verdict**, every time.
5. **What would make me abandon H1:** a null at n_days = 212 with the CI inside ±5%. That would mean
   any real effect is smaller than half of `funding_hot`'s, and therefore too small to size on.

## 10. Known limitations, acknowledged in advance

- **OI history is not recoverable.** The exchange serves no history for it — verified, HTTP 422 on
  every history endpoint — so this study can only ever use data collected from 2026-10-09 forward.
  There is no way to shorten the wait.
- **Six coins is a thin cross-section.** Terciles on six coins means two per bucket. The day-clustered
  CI accounts for this honestly, but it is the main reason the MDE is as large as it is.
- **ρ = 0.33 was measured on funding, not OI.** OI correlation may be higher or lower; it will be
  measured and reported at the interim look, and if it is materially higher the MDE table above is
  optimistic and I will say so.
- **`har_move_pct` is the server's forecast**, so this tests OI's value *beyond that specific
  forecast*, not beyond the best possible one.
- One bot, one venue, one regime.
